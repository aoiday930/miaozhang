# 喵账 · 养猫记账

> 跟猫说一句话就能记账。每天没超预算，就能用积分喂猫。

一个自带养成属性的记账工具：**你说「今天中午吃了碗牛肉面38块」，猫就帮你记好账**；当天支出没超预算，就能获得积分，拿积分换猫粮喂猫。用「养猫」这件事，把反人性的记账变成有反馈的习惯。

在线体验：https://aoiday930.github.io/miaozhang/

> 📱 手机浏览器打开上面的网址 → 菜单里选「添加到主屏幕」，就能像 App 一样全屏使用（PWA，支持离线打开）。

---

## 功能

- **对话式记账**：说一句自然语言，自动识别金额、分类、日期
- **确认机制**：识别结果先给你确认，可改金额/分类/日期，确认后才入账（避免记错账）
- **多笔识别**：「早上打车15，中午吃饭25，晚上超市买了80」→ 拆成 3 笔
- **记账分类**：餐饮、交通、购物、娱乐、住房、其他
- **日历视图**：按月显示每天的支出，没超预算显绿、超预算显红，点某天看当天明细
- **按天结算**：当天不发积分，**第二天**才结算前一天——没超预算 +10 分，连续 3 天 +5、7 天 +5
- **积分商城**：10 种猫粮（小鱼干、牛奶、苹果干、猫条、鸡胸肉、辣条、猫罐头、冻干、三文鱼、猫蛋糕），价格/饱腹度/成长值各不相同
- **宠物养成**：手绘 SVG 猫，会眨眼、摇尾巴、呼吸；三种情绪（开心/普通/饿），饿了会流口水
- **数据本地保存**：用 `localStorage` 存在浏览器里，不上传任何服务器
- **PWA**：可添加到手机桌面，离线可用

## 技术实现

**零依赖、零后端、单文件架构**：原生 HTML + CSS + JavaScript，不引任何框架和第三方库，直接放静态托管就能跑。

### 核心：本地规则解析器

产品的关键假设是「AI 能不能听懂口语化的记账句子」。在引入任何大模型之前，先做了一个**纯规则的解析器**做基线验证，流程是：

```
整句 → 非记账词过滤 → 按标点拆句 → 逐句抽金额 → 分类 → 识别日期 → 待确认
```

几个具体设计：

1. **金额抽取按优先级逐层降级**：`46块8` 这类口语小数 → 阿拉伯数字+单位 → 中文数字+单位（含「三十多」）→ 「花了/打完折」后的裸中文数字 → 「人均/一共」后的数字 → 兜底的裸数字（正则排除日期和电话）。
2. **中文数字转换**：自己实现了一个小的中文数字解析（支持 十/百/千），处理「一百」「二百六」「三十」这类写法。
3. **上下文兜底分类**：拆句会丢上下文（例如「人均80」本身没有食物词），所以先用**整句**算一次分类，分句判不出类别时继承整句结果。
4. **非记账过滤**：`工资 / 到账 / 省了 / 退款 / 报销` 等词命中则不入账，避免把收入和退款记成支出。

### 基线测试结果

用 25 句真实口语（含多笔、模糊金额、中文数字、退款、非记账句）做基准测试：

| 指标 | 规则版成绩 |
|---|---|
| 记账判定（该不该记） | **96%**（24/25） |
| 金额识别准确 | **88%**（22/25） |
| 分类准确 | **92%**（23/25） |

**结论：不依赖大模型也能覆盖大部分场景**，所以产品当前采用「规则解析 + 用户确认」，把 AI 留给长尾兜底（成本更低、响应更快、且不把账目数据发往第三方）。

## 本地运行

不需要构建、不需要装依赖：

```bash
# 直接双击 index.html 即可（部分浏览器下 PWA 功能需要在 http 环境）
# 或者起一个本地静态服务：
python -m http.server 8000
# 然后访问 http://localhost:8000
```

> PWA 的「添加到主屏幕」和 Service Worker 需要 **HTTPS 或 localhost** 才生效，所以正式体验请用 GitHub Pages 的地址。

## 已知限制

- **乘法/平摊**：如「四杯，一杯15」目前只记 15，未支持自动相乘
- **退款**：含「退了」的整句会被整体跳过，未做「部分退款」处理
- **外币**：目前识别金额但不做汇率换算
- **多笔金额归并**：一句里多笔时按总额展示，未逐笔确认
- **数据仅存本地**：换浏览器或清缓存会丢，尚未做云同步

## 项目背景

一个人做的小项目，目标是验证「**用养成机制降低记账门槛**」这个想法是否成立。

从产品假设出发先做规则基线、再用真实语料量化准确率、最后决定要不要引入模型 —— 这个过程比堆功能更重要。
